# 主链路问题库

按当前范围选择问题。以下是查证方向，不是对目标仓库存在这些设计的断言。

## 整体与 Agent Loop

- 用户输入从 UI/CLI/API 到哪里？经过哪些进程、队列、控制器或运行时？谁拥有任务、session、turn、run 的状态和身份？
- 一次模型调用和一次用户回合边界是否相同？循环由谁驱动，工具结果何时触发下一轮？
- 继续、完成、工具等待、权限等待、重试、取消、失败的条件和转换是什么？谁有权发起转换？
- 超时、断连、迟到事件、重复提交或重启如何处理？重试单位是什么，有无副作用重复风险？
- 用真实入口至结束的路径验证模型，不能用文件依赖图代替执行链。

## 会话、消息与请求

- session 如何创建、选择、加载、切换、分叉和恢复？持久化身份与运行时实例如何关联？
- 当前会话的冷恢复、引用其他会话、跨会话长期记忆是否是不同入口？另一会话的历史会自动注入、仅给读取提示，还是经专用工具按需提取？
- 每轮消息从哪些来源构建？系统指令、项目指令、Skill、工具定义、用户输入和历史在何时注入，优先级如何形成？
- 持久化记录、内存消息、Provider 请求、UI 事件分别是什么结构，哪些字段被添加、删除或重排？
- 历史选择如何保持 tool call/result 配对？中断和部分工具结果如何表示？
- thinking/reasoning 是独立字段、内容块还是展示事件？如何保存、重放、过滤或转换？签名和 Provider 差异是否影响请求有效性？
- 多模态、流式增量和最终消息如何合并？完成事件与持久化先后是否有约束？

## 工具系统

- 工具在哪里定义、注册、筛选、描述并传入模型？参数经过哪些类型和运行时校验？
- 谁决定串行或并行，是否按工具类型、权限或副作用分组？并发限额来自哪里？
- 区分启动、完成、发事件、写记录和请求组装顺序。关联 ID 如何跨层传递？
- 单个失败是否影响批次？超时与取消是否传到执行层，迟到结果如何处置？
- 大输出在何处测量和截断，是按字符、字节还是 token？完整内容是否落盘，由谁管理路径、生命周期和访问权限？
- 模型如何知道输出被截断，如何恢复读取？后续读取是否再次受预算约束？UI 展示与模型可见内容是否不同？
- 把执行器捕获、工具适配器格式化、通用结果序列化、持久化 artifact 和 Provider 回灌分层追踪。必须说明哪一层仍保留完整字节、哪一层只有预览，以及后层落盘能否补回前层已经丢弃的内容。

## 上下文、压缩与缓存

- 预算包括哪些部分，token 估算何时发生，预留多少响应或工具空间？使用哪一个模型限制？
- 按需加载在哪里触发，历史裁剪与压缩有何不同？谁拥有变更后的上下文？
- 压缩如何构建摘要请求、处理未闭合工具调用、选择保留窗口？摘要失败、取消、超限如何处理？
- 摘要如何写入、替换和复用；重启后是从摘要继续还是重建？下一轮 Provider 请求实际包含什么？
- 对 Plan、Skill、Memory、Plugin 等跨压缩内容，分别追目录/索引、已加载正文、执行操作和独立状态：哪些进入通用摘要，哪些原文保留，哪些由代码生成专用后置提示？展示实际 Prompt/格式化函数和一个假设任务的压缩后消息顺序。若声称存在 Skill 执行轨迹摘要，须找到其生产调用点、字段、持久化与恢复消费者；不能把通用摘要可能提及 Skill 操作说成专门的 trajectory 机制。
- 区分完整摘要压缩、工具结果局部清理及 Provider 自身的上下文处理。分别查明是否修改持久 transcript、是否只替换运行时历史、是否写边界事件，以及冷恢复能否重建相同行为。
- 若存在 JSONL/诊断日志，查明它保存的是权威 Session、某次模型请求，还是可轮转的调试投影；不要把日志中曾出现原文推断为持久会话可无损恢复。枚举或协议字段不等于当前运行时会触发该机制，应查生产调用点。
- 缓存属于 Provider prompt cache、请求结果缓存、文件缓存还是检索缓存？key、失效条件、隔离作用域是什么？不能仅看到 cache 字样就混为一谈。

## 跨模块场景

根据范围选一个正常场景及能暴露关键契约的异常场景，列出“入口 → 所有者 → 状态变化 → 持久化 → 模型输入 → 用户可见结果”。例如：两工具乱序完成且一个失败；压缩后重新请求；运行中取消后结果迟到；重启加载半完成回合。不存在的场景注明不适用，不编造。
