# 关联机制问题库

仅在范围相关或影响当前结论时加载。概览阶段可识别存在性和关联位置，不能把尚未深入的机制写成已验证。

## 记忆

- 区分历史记录、摘要、显式长期记忆、检索索引与配置。写入由用户、模型、后台任务还是规则触发？
- 存储形式和唯一写入者是什么？召回何时进入模型请求，如何排序、去重及限量？
- 作用域是用户、项目、workspace、session 还是全局？更新、冲突、删除、过期与来源可信度如何处理？
- 对去重、冲突、过期和可信度控制，区分程序化强制、文件/数据库约束和仅由提示词要求模型遵守的策略；后者不能写成系统保证。
- 没有搜索到 memory 目录不能作为不存在记忆的依据；从写入、索引、召回和请求注入路径交叉查证。

## Skills 与指令扩展

- 发现、选择、加载、执行分别由谁负责？元数据与正文是否分阶段加载？
- Skill 内容改变模型输入、注册工具还是触发宿主动作？加载边界、路径解析、优先级和上下文成本是什么？

## Hooks

- 触发点对应哪一个生命周期事件？同步还是异步，是否阻塞主链路？
- 输入输出契约、失败策略、超时、重入及取消是什么？Hook 能否改变权限、消息、工具参数或任务结果？

## 子 Agent

- 是独立运行时、同进程循环还是工具包装？父子如何传递上下文、权限、模型配置与身份？
- 共享和隔离哪些状态？结果如何汇合，父取消如何传播，子失败和资源清理由谁负责？
- 并行带来的独立证据与一致性责任由谁承担？不要把提示词“委派”直接等同于独立 Agent。

## 权限与配置

- 权限在哪层判定与执行？用户批准如何绑定具体动作，是否缓存或复用？配置覆盖顺序与作用域是什么？
- 工具定义可见性和实际执行授权是否一致？拒绝、等待、撤销和恢复如何进入状态机？
- 本地/远程、平台和 Provider 差异通过什么边界实现？追踪对本批结论有影响的变体。

## 可观测性与测试

- 日志、事件和追踪是否能关联 session/run/tool call？观测是否覆盖终止、重试与取消？敏感字段如何处理？
- 测试验证真实契约还是只模拟内部实现？哪些层被 mock，哪些异常场景缺少覆盖？
- 阅读实际 package 配置和测试文件确定命令，不假设统一测试入口。区分环境失败、既有失败与当前验证发现的问题。
