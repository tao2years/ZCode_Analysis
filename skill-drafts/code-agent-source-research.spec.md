# Code Agent 源码深度研究 Skill 设计约定

状态：用户已确认设计，待生成验证与真实试用；不安装。

## 产品规则

面向熟悉 Agent 开发的读者，以中文总分总报告还原本地 Code Agent 的运行模型、技术方案、设计取舍与迁移条件。支持系统研究和专题深入两个入口，先整体后深入；复用已有成果并增量维护。系统研究在全景建立后确认一次深挖重点，再自主完成。本 Skill 的创建访谈不在每次使用时重复。

质量优先；指定专题优先于必要上下游、其他核心机制和可选扩展。允许有边界的未知，不将缺少证据写成否定结论。难点使用例子，指定专题按整体流程与子步骤展开。

## 所有者与接口

研究 Agent 维护目标仓库内独立的 research/code-agent/ 目录；index 是当前研究范围、版本、状态与文档导航的入口，专题保存细节，Overview 和系统结论引用这些细节而不复制证据台账。用户指定输出位置时遵从用户。

输入：仓库位置、研究意图，可选专题与已有研究目录。输出：index、Overview、专题、系统结论、证据和续做记录。更新源码基线时按变更影响定向复核，保留未受影响内容；不能把未复核文档直接标为新版本有效。

## 执行边界

适配 Codex、Claude Code 等本地 Agent，不依赖专有工具。默认允许源码与历史阅读、相关测试、依赖安装、隔离临时验证脚本、网络查证和可用子 Agent。没有费用预算流程。使用 Codex 研究不等于已完成目标项目的模型请求实测。外部验证仍依赖可用配置、凭据和环境授权。不默认修改产品代码，不安装本 Skill。

## 验收场景

1. 新仓库：建立运行模型后确认一次范围；不把目录树当 Overview。
2. 已有全景后指定压缩专题：复用全景，解释摘要、替换、重建、续跑及关键失败分支；必要时更新旧结论。
3. 版本变化：定位受影响文档和证据，未复核部分标明旧基线或待复核。
4. SDK 取消行为无法实测：交代查证范围、影响和后续办法，以未知收束而不声称生效。
5. 中断后另一 Agent 接续：从 index 与进度恢复范围、证据、疑点和下一步，不重复已完成研究。
6. 小范围真实试跑：用户选定仓库与范围后检查产物行为，修订 Skill；没有执行条件则交付方案并标明尚未实测。
